## [D5T1 Cubic?](https://atcoder.jp/contests/abc238/tasks/abc238_g?lang=en)
### sol

简单做法是莫队。复杂度可以是 $O(n \sqrt n)$ 的，但是需要一定优化。我们发现大于 $\sqrt x$ 的质因数最多只有 $1$ 个，所以可以通过一个桶来记录这些因数。而对于小的因数，每个询问直接暴力枚举所有因数即可。

当然，这个题有 $O(n \log n)$ 的做法。我们考虑问题相当于所有的质因数的数量都是 $3$ 的倍数。这是一个套路，我们可以给每个数随机赋值 $[1, k)$，然后如果所有的数都能被 $3$ 整除，那么它们的和也一定能被 $3$ 整除。这样的话，我们就多这样赋值几遍，然后每次查询就看这些和是不是能被 $3$ 整除即可。时间复杂度的瓶颈在于分解质因数。

## D7T2 Are
### statement
有一个评测机和一堆提交，对于每个提交，如果全部测试点通过，返回最大时空，否则在第一个错误测试点上停下来，返回评测状态和已经评测的部分的最大时空。要求保留最少的测试点，使得评测结果不变。
### sol
其实比较好想。我们考虑 $f_{S,M,T}$ 表示 $S$ 中的评测状态已经满足，$M$ 中的空间已经满足，$T$ 中的时间已经满足。

这样的话状态有点爆炸。但是我们发现，如果一个评测状态已经满足，那么必然有空间和时间都满足，否则这个东西一定不合法，所以得到 $S \subseteq (M \cap T)$。这样的话，状态就是 $O(5^n)$ 的。

转移的时候，考虑一个状态加上一个记录会有什么变化。要注意不能让时空超过最大值，评测状态一定要和最初相同。

枚举的时候我们可以通过预处理，得到加上一个测试点以后对所有评测的状态，可以做到 $O(1)$ 转移。于是复杂度 $O(n5^n)$。

### think

1. 考虑压状态。把两个独立的集合变成超子集关系可以少一个底数。

## [D1T2 The Way Home](https://codeforces.com/contest/1801/problem/D)

### sol

首先考虑在一些特殊的图上怎么做。

- $a_1$ 为最大值，这种情况下我们一定会在 $1$ 搞足了钱再走。
- 图是一个外向树。这种情况下我们发现只有一条路可以到达终点，那么这个问题就变成了在链上的问题。这时我们发现一个问题：如果只记录在 $i$ 位置的最小工作天数是不够的，因此我们换一个角度考虑：**钱并不一定要在需要的时候再挣，而是在需要的时候从前面拿**。这样的话，问题就比较简单了，因为在最优的策略下，钱只会在前缀 $\max$ 处取，那么如果钱不够了，我们只需要到上一个前缀 $\max$ 的位置再“取”一些钱回来就可以。此时，我们需要发现一个重要结论：**工作时间和剩余价值是严格偏序的，因为如果我们要回头取钱的话，只要一直往前走，不够了再去一定不劣**。这样的话，我们顺带记录目前剩下的最大钱数量就可以了。也就是说，答案应当保证工作天数。
- 图是 DAG。区别是这里可能有很多链。其实区别不大，我们仍然用一个 DP 来计算最小天数，但这里我们并不知道哪里是上一个最大值（因为可能从很多地方转移过来），因此再记录上一个最大值位置即可。

这样的话，正解其实也就差不多了，由于无法直接 DP 转移，我们可以考虑用 dijkstra 转移。

### think

1. 特殊图上的最优性问题可以考虑 DP，到一般图上可以改成最短路。
2. 考虑操作的所有贡献区间（在本题中就是前缀 $\max$ 到下一个 $\max$ 的区间），这些位置可能都存在贡献。

## [D5T2 [CEOI 2022] Homework](https://www.luogu.com.cn/problem/P8997)
### sol

发现答案一定是连续的一段。

这个题有一个 DP 做法，通过看树上小于 $x$，大于 $x$ 需要多少数，可以二分。这是我场上的想法，但是比较可惜没有实现。

但是实际上不需要。我们可以发现，父亲的连续段和左右儿子的连续段有关。具体而言，如果 $L$ 表示下界，$R$ 表示上界，大概是这样：

|$a_i$|$L_i$|$R_i$|
|---|---|---|
|$\max$|$L_{l_i} + L_{r_i}$|$\max(R_{l_i}, R_{r_i})$|
|$\min$|$\min(L_{l_i}, L_{r_i})$|$R_{l_i} + R_{r_i} - 1$|

其中，取最值的两个是好理解的，难点在于两个相加。官方题解证明方法如下（这里以最大值为例，最小值同理）：

> 假设左边有 $A$ 个叶子，右边有 $B$ 个节点。令 $a$ 表示 $L_{l_i}$，$b$ 表示 $L_{r_i}$。
>
> 定义所有小于等于 $a + b - 1$ 的点为“小点”，假设左边有 $x$ 个小点，右边有 $y$ 个小点，那么我们可以得到 $x + y = a + b - 1$，那么必然有 $x < a$ 或者 $y < b$ 成立。
>
> 一个关键的想法是：**一段的最小值实际上表示的是最小的排名**。那么，由于上面两个式子中一定有一个成立，左子树第 $a$ 大或者右子树第 $b$ 大的数就会比较大，从而不能够取得 $a + b - 1$。

那就没问题了，直接从下往上合并即可。

### think

1. 考虑对信息扩展，一个数据可以从更高的角度理解，并且得到更加通用的结论。（从值到排名）

## [D5T3 [ARC174E] Existence Counting](https://atcoder.jp/contests/arc174/tasks/arc174_e)

### sol

考虑正难则反。

可以先挨个 $t$ 枚举。首先找到所有的排列（$A^k_n$）。然后我们去掉所有不包含 $t$ 的排列（$A^k_{n - 1}$）。

现在比较困难的是字典序。我们需要去掉所有字典序大于 $B$ 的序列。考虑枚举字典序是在哪个位置超的。在这个位置前面的数都要正好卡在 $B$ 位置，这个位置会有 $n - B_i$ 种超过的方案。但是并不是每个都能选，需要再记录某个位置前面的数中，大于它的数有多少个。这个东西树状数组记录即可，记为 $u_i$。后面的数可以任选，方案 $A_{n - i - 1}^{k - i - 1}$。整理一下，得到：

$$\sum_{i=1}^n(n - A_i - u_i) \times A_{n - i}^{k - i}$$

但是这样的话会把“字典序大于 $A$ 并且不包含 $t$”的序列算两遍，因此还要加上这个。考虑还是枚举，但是不能选 $t$，也就是说要减去选择 $t$ 的情况。实际上也比较简单，只需要在上面的式子加上一步就可以：（实际上还有一个隐含的要求，就是前 $i - 1$ 个数中不能存在 $t$。）

$$\sum_{i=1}^n(n - A_i - u_i - [B_i < t]) \times A_{n - i - 1}^{k - i}$$

然后把这些式子整合起来就得到了最终的答案。

但是这样比较慢，因为我们要对每个数都计算一遍，显然很麻烦。发现其实只有最后一部分和 $t$ 有关系，所以前面三部分可以直接处理。而最后这一部分可以考虑先把最开始 $1$ 的情况处理出来，然后考虑每次当 $t$ 增加的时候，如果发现 $t = B_i + 1$，那么答案就会减少 $A_{n - i - 1}^{k - i}$，而如果一个数等于 $A_i$，那么后面的贡献就都不能算了，只能计算 $[1, i]$ 的答案。因此就可以用树状数组来进行单点修改，区间查询。

### sol

最终的答案一定是一车首尾连续区间。

注意到如果有奇数个区间的话，一定有一个不动的（因为他移动对于其他区间的答案没有影响）

所以我们可以考虑多次 DP，枚举一个不动的区间。但是这是多余的，因为左右两边的区间总数一定是相同的，所以中间的贡献容易算出，这样的话只需要一个 DP，$f_{i, j, 0/1}$ 表示左边 $i$ 个，右边 $j$ 个，中间的是否被选中就可以了。

## [D1T3 Campus Partition](https://contest.ucup.ac/contest/1440/problem/7884)

### sol

注意到答案一定是若干条链，其中两头分别是最大值和次大值，否则这个链一定可以被拆开，贡献显然会变大。

如果树是一条链的话，我们可以直接 DP 算贡献，那么用一个数据结构维护最大值和次大值就差不多了。

在树上的话我们可以记下一个子树的最大贡献。但是问题是链可以跨过子树合并，那么再开一个状态，记录有一条到根的链还没有贡献。

记 $f_{i, x}$ 表示以 $i$ 为根的子树中，有一条端点点权为 $x$ 的未贡献链。特别地，我们记 $g_i$ 表示以 $i$ 为根的子树全部匹配。那么每次合并就不难写出转移：

$$f_{i, x} = \max\{f_{i, x} + g_v, \sum g_v + f_{v, x}\}$$

$$g_i = \max\{g_i + g_v, f_{i, a}+f_{v, b}+\min\{a, b\}\}$$

其中 $f$ 可以 $O(n)$ 转移，考虑使用线段树合并，同时处理 $f_{i, a}+f_{v, b}+\min\{a, b\}$，即可做到 $O(n \log n)$ 的总复杂度。

### think

1. 关于“最大值”和“次大值”的问题考虑只有两端。
2. 对于链上问题，考虑用一个 DP 记录“底到根”的半条链，然后两条拼一条。
3. 线段树合并可以处理一些神秘的东西。



## [D2T3 Djangle 的数据结构](https://codeforces.com/gym/105992/problem/E)

### sol

如果不带推平，每个数都只会减小。注意到 $\gcd$ 的性质，最多变化 $O(\log V)$ 次，那么我们记录区间的 $\text{lcm}$，假如说当前要取 $\gcd$ 的 $x$ 满足 $\text{lcm} | x$，我们就没有必要再修改，否则直接暴力递归修改，复杂度 $O(n \log n \log V)$。

然后考虑如果有修改的话，我们的这个方法看起来依然很对，不过需要一些更精确的分析。

假设线段树的势能为所有的区间内部值全部相同，而区间的父亲不全相同的节点的 $\log V$ 的和。

考虑每一种操作：

- 操作 1 会影响 $O(\log n)$ 个节点的势能，总共会增加 $O(\log n \log V)$ 的势能。
- 操作 2 最多会把两个原来相同的区间裂开，于是和 1 的势能增加级别相同。
- 操作 2 会至少使得势能减小 $1$。

这样的话，总共的复杂度 $O(n \log^2 n \log V)$ 的。

### think

1. 考虑 $\gcd$ 的经典结论（减少 $O(\log V)$ 次）
2. 数据结构题目可以尝试通过均摊的方式证明复杂度，尤其是在某些时候一个算法非常高效的时候。
3. 考虑一个操作对于两个边界的影响。包括颜色段均摊等算法其实都考虑到了一个区间操作会拆开两个端点所在的区间。

## [D1T4 Inverse Inversions](https://codeforces.com/contest/1540/problem/D)

### sol

发现序列一定是唯一的，因为 $i - b_i$ 就相当于是 $p_i$ 在前缀上的排名，所以构造就相当于插入排序。

我们把这个东西形式化一下，也就是说，初始的时候 $p_i = 0$，每次加入 $i$ 的时候 $\forall j < i \wedge p_j \geqslant i - b_i, p_j \leftarrow p_j + 1$。

这样直接构造的话，复杂度 $O(n^2)$，不能接受。我们可以换一个角度来想，对于一个 $i$，它一定是被后面的一些 $b_i$ 所影响，因此我们考虑开一个线段树，考虑一个分段函数 $f(x)$，表示 $x$ 从左端点进入，从左端点到右端点，出来的时候会变成 $f(x)$。这个函数一定只有 $O(len)$ 段，并且每一次变化都只会 $+1$。那么我们其实可以维护一个 $a_i$ 表示最小的 $x$ 使得 $f(x) - x \geqslant i$。

合并时，如果直接暴力合并，复杂度 $O(len^2)$。发现大段的 $a$ 可以写成小段卷积的形式：（设 $h$ 为大段的 $a$，$f$，$g$ 表示小段的 $a$）

$$h_k = \min_{i+j=k} \{ \max (f_i, g_j - i)\}$$

也就是说，枚举左边加了 $i$，右边加了 $j$，看两个谁先达到要求。

注意到如果 $k$ 从 $(i, j)$ 转移过来，$k + 1$ 只会从 $(i + 1, j)$ 和 $(i, j + 1)$ 转移。其本质原因是 $i, j$ 能多贡献就多贡献，如果回退，一定导致另一个增加，不会优。因此我们得到了 $O(len)$ 的转移。整个复杂度是 $O(n \log n)$。

查询的话，我们考虑在一些段上二分，复杂度 $O(\log^2 n)$。

接下来考虑修改。如果单次直接修改整个线段树的话，其复杂度将会是 $O(n)$ 级别。这种两个复杂度不平衡的问题我们经常使用分块平衡复杂度：对每一块开线段树，然后块间就和线段树完全相同，因此复杂度为 $O(\frac{n}{B}\log n)$，而修改的话就是块长 $O(B)$。平衡一下，得到 $B=\sqrt {n \log n}$，总复杂度 $O(n \sqrt {n \log n})$。

### think

1. 对于这种“被某些位置影响”的操作，可以尝试线段树走路。
2. 使用分块平衡复杂度。
3. 借助函数的性质，得到一些好结论。

## D3T4 心口的鼻息
### statement

> 给定一个网格，每个网格有D表示向下走，R表示向右走，B表示都行。多次询问，每一次查询两个点最少要走多少步才能碰面。

### sol

考虑如何判定一个点 $(a, b)$ 能否走到另一个点 $(c, d)$。

我们找到 $(c, d)$ 所在的直线 $x + y = c + d$。在这条线上，我们可以找出 $(a, b)$ 能到达的最靠下的点和最靠上的点。$d$ 一定需要属于这个区间。

根据这个条件，我们如果找出所有的这样的直线，会发现它形成了一个轮廓，那么 $(c, d)$ 必须属于这个轮廓内部。

另一方面，我们需要保证 $(c, d)$ 的最长路径大于等于两点的曼哈顿距离。显然这是必须的，但结合两个条件，发现其实已经充要了，因为 $(c, d)$ 的最长路一定走着走着就走到轮廓上了，而轮廓一定可以走到 $(a, b)$。

那么正解就可以考虑枚举走的步数。这样一来，我们就能确定交点所在的直线了。

对于判定，如果在这条直线上两个点能相遇，那么在两个点能到达的上下界的四个点中，一定有能够相遇的。原因是考虑轮廓，如果轮廓有交，那么从交点开始，两个轮廓就都可以到达了；如果轮廓无交，那么它们就显然不能相遇。这样的话，我们发现答案具有单调性，可以二分 $k$。瓶颈在于如何确定这四个端点。

一个隐含的逻辑是：新的“最靠上”的端点一定是从之前的“最靠上”的端点到达的。所以我们可以通过倍增搞。单次查询复杂度 $O(\log ^2 n)$。

### think

1. 判定性的问题可以考虑多个必要条件叠加。
2. 当判定的条件很多的时候，考虑用端点位置的信息来代替整个区间。

## [D2T4 LJJ 爱数树](https://www.luogu.com.cn/problem/P4845)

### sol

考虑 DP。由于子树里面的摄像头会影响到外面，我们不好设计状态，所以我们反过来考虑能否直接钦定一些点是有贡献的，一些点是没贡献的。**这里我们不考虑这个点是不是被照到，而是考虑这个点是不是应当被照到**。

这样的话，我们记录一个 $f_{i, j, k, l}$。其中：

- $i$ 表示以 $i$ 为根的子树。
- $j$ 表示已经放了 $j$ 个摄像头。
- $k$ 表示钦定要贡献的点中，没有被照到的深度最大的节点到 $i$ 的距离。
- $l$ 表示最浅的摄像头到 $i$ 的距离。

然后我们发现这个东西有点若智，因为如果下面有一个需要贡献的节点没有被照亮，你就一定需要把它和它的祖先全都照亮，那么下面的摄像头就根本没用，否则下面的摄像头是有用的。

所以我们可以只记录这两个信息中的一个，然后再加一个 $0/1$ 状态来表示记录了哪一个。

也就是说，可以记录 $f_{i, j, k, o}$。如果 $o = 1$，表示下面还有没有照亮的节点，用 $k$ 记录这个点到 $i$ 的距离，否则记录最浅的摄像头到 $i$ 的距离。

我靠什么屎状态，转移起来比较难写方程，因此我们直接上伪代码了。（这是刷表法。）

```python
for_each(j:[0,K], k:[0,K], op:[0,1]):         # i的状态
    for_each(j_:[0,K], k_:[0,K], op_:[0,1]):  # v的状态  
        if (op, op_) = (0, 0): new_op = 0, new_k = min(k, k_)
        if (op, op_) = (1, 1): new_op = 1, new_k = max(k, k_)
        if (op, op_) = (0, 1):
            if k + k_ >= r: new_op = 0, new_k = k
            else: new_op = 1, new_k = k_ + 1
        if (op, op_) = (1, 0):
            if k + k_ >= r: new_op = 0, new_k = k_ + 1
            else: new_op = 1, new_k = k
        new_j = j + j_
        new_f = f + f_
```

我们考虑每一个节点上枚举了什么？我们枚举了 $O(r)$ 的两层深度 $k$，$O(k)$ 的两层摄像头大小 $j$，所以总共是 $O(n^3)$ 的。（因为如果 $kr \ge n$ 就直接输出 $n$）

考虑优化。发现两层枚举 $k$ 是多余的，因为新的 $k$ 只会有两种可能性：$k$ 和 $k\_ + 1$。这两种情况分别对应 $v$ 的前缀最大值和后缀最大值，这样的话我们就少枚举了一个 $r$，这样复杂度就是 $O(n^2)$ 了。（两层枚举的时候通过优化可以使得均摊复杂度可以少一层）

## [D5T4 小 K 与毕业旅行](https://www.luogu.com.cn/problem/P5606)
### sol

出题人去掉了 $50000$ 且没有特殊性质的分，这样的话就不需要多项式了。

发现这个问题如果直接 DP 的话要考虑的东西太多了，而实际上 DP 的顺序对答案是没影响的（就是说你只要能把这种顺序的转移说圆就是对的），我们考虑换一个顺序 DP。

首先考虑大于 $0$ 的部分分。如果一个点能够和已经扫到的所有点合并，那么我们就不需要记录之前选了哪些东西了，而只需要关心选了多少。

但是我们显然找不到一个这样的构造方式，~~这玩意不应该随便hack~~比如说如果是 $1,2,3,4$，$w=4$，那么 $4$ 就肯定不满足，因为如果它放第一个，那么后面的就会无法匹配，反之就会导致他不能匹配前面的。于是可以再设计一种类型，它和前面的所有数都不能匹配。这样的话似乎就可以构造了。我们对所有的数从小到大排序，把最小的和最大的相乘，如果大于 $w$ 证明最小的可以和所有数匹配，把他放在当前顺序的前面，否则就把最小的放在最前面。这样的话，上面的序列的一个合法顺序就是 $2,3,4,1$。

有了这个顺序我们就可以搞连续段 DP 了。如果它可以和前面任何一个数匹配，我们就可以添加新段、合并段或者扩展段，否则就只能添加段。

这样是 $O(n^2)$ 的。考虑有正有负的话，正负一定可以互相匹配，那么就可以把答案表示成正负交替的很多段。

对于 $n$ 更大的 $a > 0$ 的部分，我们发现这个过程可以优化，如果把刚才的能否和所有“之前”的匹配改成“之后”的话，就可以直接考虑插入而不是连续段，看有多少个位置可以插入。

显然只有两个可以向后匹配的数中间可以插入。如果这个数可以匹配，那么它的两边还是可以插入，相当于多了一个空位，反之相当于把一个能插入的空位占满了，就不能继续插入了，相当于减少了一个空位。**这样实际上就不是 DP 了**。复杂度 $O(n)$ 加上排序的 $O(n \log n)$。
