# 支配对类
这类问题通常是给定一个结构，要求查询区间上两个位置的某种贡献的最小值或者最大值。如果直接找的话复杂度是 $O(n^2)$，但是通常可以找到一种方式，只保留其中的一些点对（通常是 $O(n \log n)$），这样的话整个问题的复杂度就降下来了。保留下来的部分就叫做这些点对的一个支配对。

## [Souvenirs](https://codeforces.com/problemset/problem/765/F)
这个恐怕是最经典的题目了。

考虑对于一个位置 $i$，有多少位置可以和 $i$ 产生贡献？

首先 $i + 1$ 一定可以和 $i$ 产生贡献。

对于 $i + 2$，先不考虑 $a_{i + 2} < a_i$ 的情况。在前面两个值的中间分开，假如说 $a_{i + 2} > \frac{a_i + a_{i + 1}}2$，就说明这个点应该是和 $i + 1$ 产生贡献是更优的。

反之则会和 $i$ 产生贡献，这样的话这条分界线就向下移动一半。因此只需要每次找到后面第一个在区间内的值。这可以通过主席树维护。当然还需要考虑小于的情况，这可以反过来计算。最终会得到 $O(n\log n)$ 个点对。

将这些点对放到平面上，每次相当于查询一个矩形内的点的最小值。再观察一下不难发现其实由于下面一半是没有点的，所以可以改成计算右下方的点，这可以扫描线做。

## [Minimum Xor On Segment](https://vjudge.net/problem/CodeChef-MINXORSEG#author=translator:1281309:zh)
和上一个题的思路差不多。

假设 $j$ 一定会和 $i$ 产生贡献。考虑一个 $k$ 位置会不会产生贡献：

首先将三个数表示成 $0/1$ 串，求出它们的 LCP。这段所有的贡献都没有区别。

接下来考察下一位。假如说 $i$ 和 $j$ 在这一位是相同的，那么新的这个一定没用（因为前面是 LCP，所以这一位一定不同）。因此只有可能是 $i$ 和 $j$ 不同且 $k$ 和 $i$ 这一位相同。这样 LCP 就往后+1，而 LCP 最多只会到 $\log V$，所以同样可以求出简单的支配对。

# 对复杂维分治
如果一个题有两维限制，一维相对于另一维不好用数据结构维护，就可以尝试分治这一维，从而取消这个限制。

常见于树分治。
## [[Ynoi2004] rpmtdq](https://www.luogu.com.cn/problem/P9058)
树这一维限制非常扫码，因为没什么好的方式来维护一个区间里面的点对。而如果能够找出这个结构的支配对，那么区间这一维就变成套板子了。

考虑边分治（实际上点分治也是一样的，但是边分治好看一些）。对于一个点 $u$，定义它到当前层的中心的距离为 $d_u$。那么两点之间的距离就可以用 $d_u + d_v$ 来表示（同子树内不用管）。这样考虑对于 $u$ 这个节点，只考虑它对面那棵子树中 $d_v \le d_u$ 的点（反过来的可以反着再做一次），这样假如有两个点 $j$ 和 $k$，$j$ 和 $k$ 的距离是小于 $d_j + d_k \le 2 \times d_u$ 的，因此其实除了前驱后继都可以直接扔了。这样就又转化回了数点问题。

## [TEST_199](https://www.luogu.com.cn/problem/U559574)
这个和最开始那个的区别就是多了个 $b$。

假设存在一种求支配对的方式，可以让不管 $b$ 怎么变，这个点对都保留了所有的可能解，那么将一个点的颜色定义为 $b_i \oplus b_j$ 就变成了矩形点反色、矩形查白点。这可以 KDT 做，加上一些随机优化复杂度就比较正确了。

接下来就是如何找到这种支配集。显然之前的那种是不可行的，但是经过一些推理可以得到结论：把原先的点数量扩大一倍就可以。

依然是考虑哪些点可以对 $i$ 产生贡献。注意此时的贡献是对于任何一种染色方式都可行的。

后面至少有两个点都是一定会产生贡献的，因为不能确定颜色。接下来考虑第三个点（假设这三个点分别为 $j$，$k$，$l$）：由于 $i$ 至少与其中一个同色，所以新的这个点就分别和 $j$ 和 $k$ 的中点比较，和之前是一样的。
